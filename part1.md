# Part 1 — Understanding the Existing Codebase & Setup

## 1. Project Structure

```
fastapi_blog/
├── .gitignore
├── README.md
├── pyproject.toml
├── uv.lock
└── src/
    └── fastapi_blog/
        └── __init__.py
```

This is a **src-layout** Python package, generated with `uv init --package` (uv's package
scaffolding), not a flat single-script project. That's why there's no `main.py` at the
root — the package's entry code lives in `src/fastapi_blog/__init__.py` instead.

## 2. Key Files

### `pyproject.toml`
- Project metadata: name `fastapi-blog`, version `0.1.0`, requires Python `>=3.14`.
- Dependency: `fastapi[standard]>=0.141.1` (includes `uvicorn`, `fastapi` CLI, etc.
  via the `standard` extra).


## 3. Current State Summary
- The project is a **bare scaffold**: dependencies are declared, but there is no

## 3a. `src/fastapi_blog/main.py` (FastAPI app)

```python
from fastapi import FastAPI
from fastapi.responses import HTMLResponse

app = FastAPI()

posts: list[object] = [
    {"id": 1, "title": "Hello World", "content": "This is a post",
     "published": True, "author": "Agam"},
    {"id": 2, "title": "Hello World2", "content": "This is a post2",
     "published": False, "author": "Agam2"},
]

@app.get("/", response_class=HTMLResponse)
def home():
    return f"<h1>{posts[0]['content']}</h1>"

@app.get("/api/posts")
def get_posts():
    return {"data": posts}
```

- This is the **actual FastAPI application entry point** (separate from the
  package's `__init__.py`). It creates the `FastAPI()` instance named `app`.
- `posts` is an in-memory dummy list (no database yet) used to fake a "posts"
  resource.
- **Route `GET /`**: returns raw HTML (`HTMLResponse`) showing the content of the
  first post — demonstrates returning non-JSON responses.
- **Route `GET /api/posts`**: returns all posts as JSON under a `data` key —
  demonstrates a typical JSON API endpoint.
- Interactive API docs are auto-generated by FastAPI and available at
  `http://localhost:8000/docs` (Swagger UI) once the server is running.
- Note: `__init__.py`'s `main()` function is unrelated to this file — `main.py`
  is where the real app now lives.

## 4. Setup Steps (based on this codebase's tooling)

This project uses **uv** as the package manager and build tool.

1. **Install uv** (if not already installed):

    Linux/MacOS:
   ```
   curl -LsSf https://astral.sh/uv/install.sh | sh
   ```
   Windows:
   ```
   powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
   ```

2. **Install project dependencies** (creates `.venv` and installs from `uv.lock`):
   ```
   cd fastapi_blog/src/fastapi_blog/   
   ```

3. **Run the current placeholder entry point**:
   ```
   uv run fastapi dev main.py
   ```
   Output: `Hello from fastapi-blog!` (no server starts yet).

4. **Start the dev server** using the `fastapi` CLI bundled with
   `fastapi[standard]`, pointing at `main.py` where the `app` instance lives:
   ```
   uv run fastapi dev src/fastapi_blog/main.py
   ```
   or directly with uvicorn:
   ```
   uv run uvicorn fastapi_blog.main:app --reload
   ```
   Then visit `http://localhost:8000/` for the HTML route, or
   `http://localhost:8000/api/posts` for the JSON route, and
   `http://localhost:8000/docs` for interactive API docs.
